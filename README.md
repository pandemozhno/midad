## 0. Три железных правила

1. **Табы, не пробелы.** Один уровень = один таб. Смешение — ошибка.
2. **Символ — это символ, слово — это слово.** `+`, `==`, `&` — нотация, не сокращения, остаются как есть. `and`, `or`, `not`, `function`, `as` — полные английские слова, переводятся через `.sema`.
3. **Один `.mid` — один `module`.** Файл начинается с профиля (`@kernel`, `@flow`, `@view`, `@light`), затем `module имя`.

## 1. Профили

Профиль — это набор правил компилятора. Пишется первой строкой файла, отдельным токеном `@имя`.

| Профиль | Что разрешено | Что запрещено | Бэкенды |
|---------|---------------|---------------|---------|
| `@kernel` | `assembly`, `unsafe`, `static mutable`, `external C`, `no standard`, `entry` | `show`, `rule` | C, native |
| `@flow` | `show`, `rule when … then`, `emit`, структуры, протоколы | `assembly`, `unsafe` | C, JS, WASM, native |
| `@view` | `show`, виджеты | `assembly`, `unsafe` | C, JS, WASM |
| `@light` | шейдеры, векторы, `float32`/`float64` | `assembly`, `unsafe`, `show` | SPIR-V, WGSL |

Проверка профиля — на этапе `checker`. Нарушение — ошибка компиляции, не runtime.

## 2. Символьные операторы

### 2.1. Арифметика

| Символ | Имя | Что делает | Профиль | Пример |
|--------|-----|-----------|---------|--------|
| `+` | сложение | складывает два значения | все | `let s = a + b` |
| `-` | вычитание | вычитает правое из левого | все | `let d = a - b` |
| `-` (унарный) | отрицание | меняет знак | все | `let m = -x` |
| `*` | умножение | умножает два значения | все | `let p = a * b` |
| `/` | деление | делит левое на правое | все | `let q = a / b` |
| `%` | остаток | остаток от целочисленного деления | все | `let r = a % b` |

Целочисленное деление: `5 / 2 == 2`. Для дробей — `float32`/`float64`.

### 2.2. Сравнение

| Символ | Имя | Что делает | Профиль | Пример |
|--------|-----|-----------|---------|--------|
| `==` | равно | `true`, если равны | все | `if a == 0` |
| `!=` | не равно | `true`, если не равны | все | `if a != 0` |
| `<` | меньше | `true`, если левое меньше | все | `if a < b` |
| `>` | больше | `true`, если левое больше | все | `if a > b` |
| `<=` | меньше или равно | `true`, если левое ≤ правого | все | `if a <= b` |
| `>=` | больше или равно | `true`, если левое ≥ правого | все | `if a >= b` |

Результат сравнения — `boolean`. Сравнивать можно значения одного типа; разные типы → ошибка (кроме `int` ↔ `float`, расширение контекста — планируется).

### 2.3. Битовые

| Символ | Имя | Что делает | Профиль | Пример |
|--------|-----|-----------|---------|--------|
| `&` | побитовое И | оставляет бит, если он есть в обоих | все | `let m = status & 0x20` |
| `\|` | побитовое ИЛИ | ставит бит, если он есть в любом | все | `let m = a \| b` |
| `^` | побитовое XOR | ставит бит, если он есть только в одном | все | `let m = a ^ b` |
| `<<` | сдвиг влево | сдвигает биты влево на N | все | `let m = a << 4` |
| `>>` | сдвиг вправо | сдвигает биты вправо на N | все | `let m = a >> 2` |
| `~` (унарный) | побитовое НЕ | инвертирует все биты | все | `let m = ~a` |

Работают на целых типах (`unsigned*`, `integer*`). На `boolean` и `float` — ошибка.

### 2.4. Указатели

| Символ | Имя | Что делает | Профиль | Пример |
|--------|-----|-----------|---------|--------|
| `*` (унарный) | разыменование | читает значение по адресу | `@kernel` (в `unsafe`) | `let c = *s` |
| `&` (унарный) | адрес | возвращает адрес значения | `@kernel` (в `unsafe`) | `let p = &x` |
| `*` (в типе) | указатель | «указатель на T» | `@kernel` | `let p as *unsigned8` |

Арифметика указателей: `s + 1` — следующий байт для `*unsigned8`, следующие 4 байта для `*integer32`. Единица = `sizeof(*T)`.

В `@flow` указатели запрещены. В `@kernel` — только внутри `unsafe`.

### 2.5. Присваивание

| Символ | Имя | Что делает | Пример |
|--------|-----|-----------|--------|
| `=` | присваивание | записывает значение в переменную/поле | `self.count = 0` |
| `=` (в структуре) | инициализация поля | задаёт начальное значение поля | `count as integer32 = 0` |

Составных операторов (`+=`, `-=`, `*=`, …) **нет** — решение проекта. Пишется явно: `a = a + b`.

### 2.6. Указание типа

| Символ | Имя | Что делает | Пример |
|--------|-----|-----------|--------|
| `as` (после параметра) | объявление типа | указывает тип при `let`/`takes`/`gives` | `let x as integer32` |
| `as` (после выражения) | приведение типа | конвертирует выражение в тип | `let big = a as unsigned64` |

`as` — **одно слово**, две роли различаются позицией. В `let name as Тип = …` это объявление. В `value as Тип` — приведение.

## 3. Словесные логические операторы

Полные английские слова, не символы. Сейчас — hardcoded `Ident`, не переводятся через `.sema` (см. ограничения).

| Слово | Что делает | Пример |
|-------|-----------|--------|
| `and` | логическое И (short-circuit) | `if a > 0 and b > 0` |
| `or` | логическое ИЛИ (short-circuit) | `if a == 0 or b == 0` |
| `not` | логическое НЕ (унарный) | `if not ready` |

`and`/`or` работают на `boolean`. `not` — унарный префикс.

---

## 4. Приоритет операторов

От низкого к высокому. Один уровень — левая ассоциативность.

| Уровень | Операторы |
|---------|-----------|
| 1 (низший) | `or` |
| 2 | `and` |
| 3 | `\|` |
| 4 | `^` |
| 5 | `&` |
| 6 | `==` `!=` |
| 7 | `<` `>` `<=` `>=` |
| 8 | `<<` `>>` |
| 9 | `+` `-` |
| 10 | `*` `/` `%` |
| 11 | унарные `-` `~` `not` `*` (deref) `&` (addr) |
| 12 | `.method()` `.field` `as Type` (постфиксные) |
| 13 (высший) | литералы, `(…)`, `{…}` |

Пример: `a + b * c == d and e > 0` разбирается как `((a + (b*c)) == d) and (e > 0)`.

Скобки `( )` переопределяют приоритет.

## 5. Объявления

Каждое объявление — новая строка без отступа (внутри `module`), тело — с отступом.

### 5.1. `function` — функция

```
function имя takes пар1 as Тип1, пар2 as Тип2 gives ТипРезультата
	тело
```

- `takes` — список параметров. Без `takes` — функция без параметров.
- `gives` — тип возврата. Без `gives` — `void`.
- `return значение` — вернуть значение.
- `return` без значения — для `void`.

Пример:

```
function add takes a as integer32, b as integer32 gives integer32
	return a + b
```

### 5.2. `unsafe function` — небезопасная

```
unsafe function имя takes …
	тело
```

Внутри разрешены `*mut T`, разыменование, вызовы `external`. Только `@kernel`.

### 5.3. `let` — переменная

```
let имя = значение
let имя as Тип = значение
```

Тип выводится из значения, если не указан явно.

```
let count = 0
let mask as unsigned8 = 0x20
```

### 5.4. `static` — статическая переменная

```
static имя as Тип = значение
static mutable имя as Тип = значение
```

`static` — константа модуля. `static mutable` — изменяемая. Инициализация — только константным выражением.

```
static BUILD_ID as unsigned32 = 0x0300
static mutable uart_ready as boolean = false
```

### 5.5. `structure` — структура

```
structure Имя
	поле1 as Тип1
	поле2 as Тип2 = значение_по_умолчанию
```

Создание:

```
let p = Point { x = 0, y = 0 }
```

Доступ: `p.x`, `p.y`.

### 5.6. `enumeration` — перечисление

```
enumeration Имя
	вариант1
	вариант2
	вариант3
```

Значения в C — `Имя_вариант1`, `Имя_вариант2`. В Midād: `Имя.вариант1` (планируется, сейчас только C-сторона).

### 5.7. `protocol` — протокол (интерфейс)

```
protocol Имя
	function метод1 takes self
	function метод2 takes self gives Тип
```

Только сигнатуры, без тел. Реализация — в `implementation`.

### 5.8. `implementation` — реализация

```
implementation Тип as Протокол
	function метод takes self
		тело
```

`as Протокол` — необязательно. Без него — просто методы типа. С ним — реализация протокола (в C генерируется vtable-структура, в JS — ничего дополнительно).

### 5.9. `external` — внешние функции

```
external "C"
	function имя takes пар as Тип gives Тип
```

Только `@kernel`. Сейчас — только ABI `"C"`, только объявления (без тел). Связывание — с `libk` или системными библиотеками.

### 5.10. `module` — модуль

```
@профиль
module имя
	no standard       ← опционально
	entry имя_функции ← опционально
	…объявления…
```

`no standard` — freestanding-режим (без libc). `entry` — точка входа для линкера. Оба — только `@kernel`.

### 5.11. `rule` — правило

См. раздел 9.

## 6. Управление потоком

### 6.1. `if … otherwise …`

```
if условие
	тело_если_истина
otherwise
	тело_если_ложь
```

`otherwise` — необязателен. Вложенность — отступами.

### 6.2. `while`

```
while условие
	тело
```

Проверка перед каждой итерацией. `break`/`continue` в v0.3 **нет**.

### 6.3. `for each … in …`

```
for each имя in выражение
	тело
```

`each` — опционально: `for x in arr` эквивалентно `for each x in arr`. В v0.3 работает только для целочисленных диапазонов (`for i in 10` → 0..9); массивы — планируется.

### 6.4. `return`

```
return значение
return
```

Возврат из функции. Тип значения должен совпадать с `gives`.

### 6.5. `panic`

```
panic "сообщение"
```

Прерывает исполнение. В C → `mid_panic("…")` → `__builtin_trap`. В JS → `throw new Error("…")`. В `@kernel` — бесконечный `hlt` после trap (в реальной ОС — перезагрузка).

### 6.6. `show … as …`

```
show выражение as формат
```

Только `@flow`, `@view`. Формат — идентификатор (`text`, `number`, `boolean`). В C → вызов `__qalam_show_str/int/bool`. В JS → `console.log`. В native `@flow` — виджет в ZoomWorld.

### 6.7. `unsafe`

```
unsafe
	тело
```

Только `@kernel`. Разрешает разыменование `*mut T` внутри блока. Вне `unsafe` — ошибка компиляции.

### 6.8. `assembly`

См. раздел 10.

## 7. Типы

См. раздел 12 — полная таблица.

Указатели:

```
*Тип          — указатель на Тип (immutable)
```

`*mut` (mutable-указатель) — не реализовано в v0.3, все указатели неявно mutable.

Массивы `[Тип; N]` — **не реализованы** (спека есть, парсер не поддерживает).

Типы можно уточнять при `let`, `takes`, `gives`, `static`, полях структур.

## 8. Доступ и вызовы

### 8.1. Вызов функции

```
имя(арг1, арг2, …)
имя()
```

Скобки обязательны даже без аргументов: `main()`, не `main`.

### 8.2. Доступ к полю

```
объект.поле
self.поле
```

В C → `объект->поле` для указателя, `объект.поле` для значения. Различие делает бэкенд, пользователь пишет одинаково.

### 8.3. Вызов метода

```
объект.метод(арг1, арг2)
self.метод()
```

В C → `Тип_метод(&объект, арг1, арг2)` или `Тип_метод(self, …)` если объект — `self`. В JS → `объект.метод(арг1, арг2)`.

### 8.4. Литерал структуры

```
ИмяСтруктуры { поле1 = знач1, поле2 = знач2 }
```

Только с фигурными скобками. Порядок полей не важен. Пропущенные поля — значение по умолчанию из объявления (или zero).

### 8.5. Группировка

```
(выражение)
```

Меняет приоритет.

## 9. Правила (реактор)

`rule` — метод, привязанный к событию. Синтаксический сахар над методом типа.

```
rule when Тип.событие then
	тело
```

С параметрами:

```
rule when Тип.событие takes пар as Тип then
	тело
```

Тело — блок операторов. Внутри доступен `self` — экземпляр типа, от которого пришло событие. `emit событие` — эмитит событие (в C — комментарий, в JS — `self._emit(...)`).

Только `@flow`. Внутри `@kernel`, `@view`, `@light` — ошибка компиляции.

Пример:

```
rule when Counter.changed then
	show self.get() as number
```

Событие `Counter.changed` эмитится из метода:

```
function inc takes self
	self.count = self.count + self.step
	emit changed
```

`emit` — только имя события без типа; тип выводится из контекста `self`.

## 10. Ассемблер

Только `@kernel`, только внутри блока `assembly`.

```
assembly
	output (порт, значение)
	input (порт)
	interrupt (номер)
	halt
	no operation
```

| Операция | Что делает | Пример | Аналог |
|----------|-----------|--------|--------|
| `output (порт, значение)` | пишет байт в порт | `output (0x3F8, c)` | `outb %al, %dx` |
| `input (порт)` | читает байт из порта | `let s = assembly input (0x3F8 + 5)` | `inb %dx, %al` |
| `interrupt (номер)` | программное прерывание | `interrupt (0x80)` | `int $0x80` |
| `halt` | останавливает CPU | `halt` | `hlt` |
| `no operation` | пустая инструкция | `no operation` | `nop` |

`input` бывает в двух формах:

1. **Как стейтмент:** `assembly` + блок, `input (порт)` внутри. Результат теряется.
2. **Как выражение:** `let x = assembly input (порт)`. Возвращает `unsigned8`.

Порты — `unsigned16` (0..65535). Значения — `unsigned8`.

## 13. Зарезервировано, но не используется

Токены, которые лексер распознаёт, но парсер не принимает. Оставлены для будущих расширений.

| Символ | Планируется для |
|--------|-----------------|
| `:` | аннотации типов в стиле `let x: i32` (сейчас `as`) |
| `[` `]` | массивы `[T; N]` и индексация `arr[i]` |
| `->` | тип возврата в стиле `fn() -> T` (сейчас `gives`) |

Кроме того, зарезервированы ключевые слова, не реализованные в парсере: `volatile` (семантика `static mutable`), составные операторы присваивания (`+=` и т.п.) — **не будут** реализованы, решение проекта.

## 14. Примеры

### 14.1. Hello, World! (`@flow`)

```
@flow
module hello

function main
	show "Hello, World!" as text
```

### 14.2. Hello, World! на русском

```
@flow
модуль привет

функция главная
	покажи "Привет, мир!" как текст
```

`главная` → `[names]` → `main`, `текст` → `[names]` → `text`. Один SEM, разные поверхности.

### 14.3. Hello на голом железе (`@kernel`)

```
@kernel
module hello_kernel
	no standard
	entry _start

function putc takes c as unsigned8
	let mask = 0
	while mask == 0
		let status = assembly input (0x3F8 + 5)
		mask = status & 0x20
	assembly
		output (0x3F8, c)

function puts takes s as *unsigned8
	let c = *s
	while c != 0
		putc(c)
		s = s + 1
		c = *s

function _start
	puts("Hello, World!\n")
	while true
		assembly
			halt
```

Здесь: `*unsigned8` — указатель, `*s` — разыменование, `s + 1` — арифметика указателя, `assembly input` — `inb`, `assembly output` — `outb`, `halt` — `hlt`.

### 14.4. ООП с правилом (`@flow`)

```
@flow
module counter

structure Counter
	count as integer32
	step as integer32 = 1

protocol Incrementable
	function inc takes self
	function get takes self gives integer32

implementation Counter as Incrementable
	function inc takes self
		self.count = self.count + self.step
		emit changed
	function get takes self gives integer32
		return self.count

rule when Counter.changed then
	show self.get() as number

function main
	let c = Counter { count = 0 }
	c.inc()
	c.inc()
```

Вывод в C-native и в Node.js: `1`, `2`.

### 14.5. Условное ветвление и цикл

```
@flow
module loop_demo

function collatz takes n as integer32 gives integer32
	let steps = 0
	while n != 1
		if n % 2 == 0
			n = n / 2
		otherwise
			n = n * 3 + 1
		steps = steps + 1
	return steps

function main
	show collatz(27) as number
```

## 15. Ограничения v0.3

Что **не** работает, хотя может быть в спецификации:

| Ограничение | Причина | План |
|-------------|---------|------|
| `and`, `or`, `not` не переводятся через `.sema` | парсер ищет `Ident("and")` буквально | добавить в keywords |
| `*mut T` | все указатели неявно mutable | Tier 1 |
| Массивы `[T; N]` | токены есть, парсер не принимает | Tier 2 |
| Индексация `arr[i]` | `[` `]` зарезервированы | Tier 2 |
| `break` / `continue` | не реализованы | решение проекта — не добавлять |
| `volatile` | парсер принимает ключевое слово, codegen игнорирует | Tier 1 |
| Протоколы через vtable | в C генерируется typedef `_vt`, но вызовы статические | Tier 2 |
| `for i in array` | работает только для целочисленных диапазонов | Tier 2 |
| Правило как реальный механизм | в C `rule` = функция, реактор вызывает её вручную | Tier 3 |
| Capability-проверки | поле `SemFn.capabilities` есть, но пустое | Tier 3 |
| WASM backend | отсутствует | Tier 1 |
| `@light` → SPIR-V | отсутствует | Tier 4 |

Всё, что **не** в этой таблице, — работает и покрыто примерами в `examples/` + `build.sh`.
